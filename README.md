# くらし

リアル時刻に合わせて、キャラクターと一緒に暮らすアプリです。
コマンドを実行するたびに、ComfyUI でその場面の画像を生成して表示します。

## 起動

```
python server.py            # http://127.0.0.1:8765/ がブラウザで開く
python server.py --port 9000 --no-browser
```

`start.bat` をダブルクリックしても起動できます。
必要なのは Python 3.8 以上だけです（追加パッケージは不要）。

最初に **設定 → 画像生成 (ComfyUI)** を開き、次の順で設定してください。

1. ComfyUI のアドレスとポートを入力する
2. 接続テストを実行する
3. チェックポイントを選んで保存する

## 仕組み

| 要素 | 内容 | 保存先 |
|---|---|---|
| パラメータ | からだ（満腹度・水分・体力・眠気・清潔・健康）／こころ（機嫌・ストレス・退屈・寂しさ・好感度・信頼・照れ・ドキドキ）。リアル時間 5 分刻みで「基本変化 + 場面の毎時効果 + 自然回帰」が進む。アプリを閉じている間の分も、次回起動時にまとめて計算する（最大 14 日） | `data/params.json` |
| 生活スケジュール | 曜日・時刻ごとの場面（場所・服装・プロンプト・毎時効果・外出／睡眠／手が離せない）。どれにも一致しない時間は「普段」の場面になる | キャラ JSON |
| コマンド | 実行条件・効果・クールダウン・行動プロンプトを持つ。実行後に一時シーン（散歩・入浴など）へ切り替えることもできる | `data/actions.json` |
| 反応 | 条件・優先度・セリフ・追加効果・反応プロンプトを持つ。「置き換え」を指定すると、行動の効果とシーン切り替えを無効にする（断る反応など） | コマンド内 |
| 状態タグ | パラメータが条件を満たすと、プロンプトにタグを加える（空腹・眠そう・照れ など） | パラメータ内 |
| 主人公 | 外見の Positive / Negative プロンプト、性格・口調、呼び方。プロンプトは保存のたびに履歴へ残る | `data/characters/*.json` |
| 着せ替え | キャラごとの服（名前・着られる条件・服装プロンプト）。サイドの「着せ替え」タブで選ぶと、システムコマンド `_dress` の反応を経て服装が差し替わる。反応の条件では `outfit=maid` のように着替え先を参照でき、断る反応（置き換え）なら着替えない。スケジュールで「服装固定」の場面（既定では睡眠中）は固定の服が優先され、既定では寝るとスケジュール通りの服に戻る | キャラ JSON の `wardrobe` |

### お出かけ・見るコマンド

- お出かけには、散歩・買い物・デート・ピクニック・ハイキング・海・遊園地・水族館・カフェ・星を見に行く、があります。
  - 季節によって反応が変わります（例: 冬の海）。季節は条件キー `season` で判定します。
- お出かけ中は「家に帰る」、ゲームや映画などの最中は「切り上げる」で、いつでも予定どおりの過ごし方に戻れます。
- 出かけるときは主人公の「お出かけ着」に着替えます。着せ替えで選んだ服は、「外に着ていける」にした服だけ、そのまま着ていきます（部屋着やパジャマのまま出かけません）。
- 見る系のコマンドは5つあります。それぞれ画像の構図が違います。
  - 様子を見る（今していることごとに描写が変わる）
  - 顔をのぞきこむ（アップ）
  - こっそり見守る（こちらに気づいていない姿）
  - 全身を眺める（服装が分かる全身）
  - 寝顔を見る

### 既定データの更新

起動時に、`data/` のコマンドとミニゲームを、最新の既定に自動で追従させます。

- 過去の既定のまま（未編集）のものは、最新の既定に置き換えます。手を加えたものは、そのまま残します。
- 新しく増えた既定のコマンドやゲームは追加します。一度消したものは戻しません。
- 既定の `actions.json` / `minigames.json` を変えたときは、コミット前に `python tools/build_default_history.py` を実行して、過去の版の指紋（`defaults/default_history.json`）を更新してください。

### 性格プリセット（セリフ集）

**設定 → 主人公** で性格を選ぶと、コマンドの反応とミニゲームのセリフがその性格の口調に変わります。
条件・効果・画像プロンプトは共通のままなので、変わるのは口調だけです。

- 既定の性格は16種類です: 素直なはにかみ屋 / 気心知れた幼馴染 / 面倒見のいい世話焼きさん / ほんわかおっとり / 箱入りお嬢様 / 気高き令嬢 / 素直になれないツンデレ / 辛口なクール / 言葉少なな無口さん / 淡々とした実務派 / 凛とした男前 / 元気いっぱい / 天真爛漫な自由人 / 人見知りの恥ずかしがり屋 / サバサバなボクっ娘 / 甘えたがり。
  - 気高き令嬢は、「ですわ」を使わない落ち着いた貴族風です。凛とした男前は、「〜だな」「〜だろう」で話す中性的な口調です。
  - 言葉少なな無口さんは、口数が少なく、気持ちが小さな仕草ににじむタイプです（例:「……ん。（ほんの少し口元がゆるむ）」）。辛口なクールとは違い、冷たくも毒舌でもありません。
  - 淡々とした実務派は、敬語なしの事務的な口調で話します。感情も事務的な言い回しのまま報告します（例:「今の、少しうれしかった。……記録しておく」）。
  - どれも約250場面について、1場面に1〜2通りのセリフがあります。
  - 選んだときに、LLM 用の性格説明と、あなたの呼ばれ方もプリセットに合わせられます。
- 一人称とあなたの呼び方は、**設定 → 主人公** で固定できます。
  - 空欄なら、性格プリセットに従います（例: ボクっ娘なら「ボク」、ツンデレなら「あんた」）。
  - 入力すると、どの性格を選んでもその一人称・呼び方になります。LLM のセリフ生成にも伝えます。
  - セリフ中では、一人称を `{fp}`（言いよどみは `{fp_st}`、例:「わ、私」）、あなたを呼ぶところを `{call}` と書きます。
- **設定 → 性格・セリフ集** で、場面ごとにセリフを見て編集・複製できます（保存先は `data/personas/`）。セリフが空欄の場面は、共通のセリフになります。
- 場面のキーは、コマンドの反応なら `<コマンドid>.<キー>`、ミニゲームなら `mg.<ゲームid>.<場面>.<キー>` です。キーは各反応の `key` か、無ければ条件式から自動で作ります（例: `talk.mood_lt_35`）。
  - コマンドや反応を追加したら、`python tools/dump_line_keys.py` で全キーの一覧が出せます。
  - `python tools/check_persona.py` で、セリフ集の抜けや書式を検査できます。

### ミニゲーム

サイドの「ゲーム」タブから遊べます。1手ごとにセリフと画像が出て、パラメータも変わります。

- **野球拳**: じゃんけんで負けたほうが1枚ずつ脱いでいきます。
  - キャラが降参したらあなたの勝ち、あなたのライフ（既定3）が尽きたら負けです。
  - 好感度が足りないと断られます。
  - 段階（既定: 靴下 → リボン → キャミソール姿 → 降参）は、服装プロンプトの追記・置き換えと、外見タグの除外で定義します。
- **あっち向いてホイ**: じゃんけんの勝者が指さし、負けた側が顔をそらします。先に3本取ったほうの勝ちです。
- **脱衣麻雀**: 二人打ちの簡易麻雀です。
  - 鳴きはなく、リーチ・ツモ・ロンだけです。主要な役（十数種と役満）があり、役なしでは和了れません。ドラと裏ドラ、フリテンもあります。
  - あなたが和了るとキャラが脱ぎ、和了られるとライフが減ります。満貫以上は2段階、倍満以上は3段階進み、役満なら一気に決着します。
  - 画像は、開始・リーチ・局の終わりで生成します。キャラはシャンテン数と受け入れ枚数で打牌を選び、相手のリーチには現物で降ります。
- **コネクトフォー / ヘックス / リバーシ**: 盤面の二人対戦です。画像は開始と決着で生成し、途中のひとことは吹き出しで出します。
  - コネクトフォーは盤の上の ▼ 投入口から落とします。コマが上から落ちるアニメーション付きです。
- **ヨット**: 世界のアソビ大全のルールに準拠したダイスゲームです。
  - 5個のサイコロを1ターン最大3回振り、残すサイコロを選んで12の役を埋めます。上段が63点以上なら+35点です。
  - キャラの番は自動で進み、何を残してどの役に入れたかを表示します。

- **花札こいこい**: 48枚の正規の札と出来役（五光・四光・雨四光・三光・猪鹿蝶・赤短・青短・タネ・タン・カス・花見で一杯・月見で一杯）で遊びます。
  - 役ができたら「あがり」か「こいこい」を選びます。7文以上と、こいこい返しは倍です。
  - 既定は3局の合計文数で勝負します。
- **脱衣ポーカー**: ファイブカードドローです。
  - 交換後に「勝負」か「倍プッシュ」を選びます。倍プッシュには、キャラが降りることもあり、受けて立たれたら2段階分になります。
  - 交換後のキャラのひとことは、ブラフのこともあります。
- **ブラックジャック**: キャラがディーラーで、17以上でスタンドします。ヒット・スタンド・ダブルができ、ナチュラルは2勝分です。先に5勝したほうの勝ちです。
- **神経衰弱**: 12組24枚です。キャラの記憶力は強さと眠気で変わり、ときどき忘れます。キャラがめくった札は位置ごと表示されます。
- **ババ抜き**: 二人で遊びます。キャラの札に指をかけると表情が変わります（嘘のこともあります）。もう一度押すと引きます。

こいこい・ポーカー・ブラックジャックは、`stages` を書くと脱衣ルールになり、書かなければ勝ち数か合計点の勝負になります。

麻雀・盤面・カードゲームのキャラの強さは、眠気や不機嫌で凡ミスが増えて弱くなります。

キャラはときどき「次は○○を出そうかな？」と予告してきます（本当とは限りません）。
**設定 → ミニゲーム** で、段階・セリフ・効果・プロンプトを JSON で編集できます（`data/minigames.json`）。

### 画像の出し方

**設定 → 画像生成** で切り替えます。

- **既存の画像からランダムにすぐ表示**（既定）: 合成後の Positive + Negative が完全に一致する画像がすでにあれば、そこからランダムに 1 枚をすぐ表示します。1 プロンプトあたりの上限枚数に達するまでは、裏で新しい画像も生成し、できあがったら差し替えます（generatw と同じ方式）。
- **毎回新しく生成する**: 毎回 ComfyUI で生成します。

どちらのモードでも、生成中に次のコマンドを実行したときは、同じプロンプトの既存画像があればそれをすぐ表示し、新規生成はしません。既存画像がなければ待ち行列に追加します（「生成中は既存画像で済ませる」設定でオフにできます）。

表示中の画像は 🎲 で同じプロンプトの別の画像に、⟳ で新規生成に切り替えられます。
索引は `data/images/index.json` です。無ければ、ログから作り直します。

プロンプトは次の順で合成し、重複するタグを除いて ComfyUI に送ります。

**共通 → 主人公 → 服装 → 場面 → 時間帯 → 状態タグ → 行動 → 反応**

### 条件式

```
free=true, mood>=50, phase=night|midnight
```

- カンマで区切った条件は AND、`|` は OR になります
- 使えるキーは次のとおりです
  - パラメータ id
  - `activity` `location` `phase`
  - `free`（外出・睡眠・手が離せない、のどれでもない）`away` `asleep` `busy`
  - `hour` `time`（`07:30` 形式で比較）`weekday` `day`（mon..sun）`weekend`
  - `absent`（最後のふれあいからの時間）`repeat`（クールダウン中の連続回数）
  - `outfit`（着せ替え中の服の id。おまかせなら空。着せ替えの反応では着替え先）

### セリフ生成

既定では、条件に合う定型セリフを選んで表示します。
**設定 → セリフ生成** で Ollama か OpenAI 互換の API を有効にすると、選ばれた定型セリフを方向性の参考にして、LLM がセリフを書きます。
LLM の呼び出しに失敗したときは、定型セリフをそのまま使います。

### ComfyUI 側に画像を残さない

既定では、ComfyUI の output フォルダには画像を保存しません。

- 生成した画像は、ComfyUI の一時フォルダ（PreviewImage。ComfyUI の再起動で消える）を経由して受け取ります。保存するのは、このアプリの `data/images` だけです。
- カスタムワークフローの SaveImage も、送信時に自動で PreviewImage に置き換えます。
- ComfyUI 側にも残したい場合は、**設定 → 画像生成** の「ComfyUI の output フォルダにも保存する」をオンにします。保存先は `output/kurashi/` のサブフォルダです（「保存先」で変更できます）。

### カスタムワークフロー

ComfyUI で「Export (API)」した JSON を登録できます。
値に次のプレースホルダを書いておくと、生成時に置き換えます。

`%POSITIVE%` `%NEGATIVE%` `%SEED%` `%WIDTH%` `%HEIGHT%` `%STEPS%` `%CFG%` `%CKPT%` `%SAMPLER%` `%SCHEDULER%`

## 生成がうまくいかないとき

画面右上のバッジ（「🖼 生成ジョブ」/「ComfyUI で生成中 …」）をクリックすると、生成ジョブの一覧が開きます。
ジョブごとに、今どの段階にいるか、経過ログ、ComfyUI の prompt_id、エラー内容が表示され、そこから取り消しもできます。
同じ内容は、サーバのコンソールと `data/server.log` にも記録されます。

| 止まっている段階 | 考えられる原因 |
|---|---|
| 前のジョブ待ち | 先に積まれたジョブを処理している。一覧の先頭のジョブを確認する |
| ComfyUI へ送信中 | ComfyUI に届いていない（アドレス/ポート、ファイアウォール、プロキシ） |
| ComfyUI のキュー待ち | ComfyUI が他の生成を処理中。ComfyUI の画面でキューを確認する |
| ComfyUI で生成中 | ComfyUI 側で処理中。ComfyUI のコンソールに進捗やエラーが出ているはず |
| 失敗 | 表示されたエラーを確認する。例: `Value not in list ckpt_name` ならチェックポイント名の誤り |

- ComfyUI との通信は、既定ではシステムのプロキシを通しません。プロキシが必要な環境では、**設定 → 画像生成** の「システムのプロキシを使う」をオンにしてください。
- 失敗のパターンは、モックで再現できます: `python tools/mock_comfy.py --fail reject|exec|hang`
