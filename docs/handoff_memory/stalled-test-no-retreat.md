関連テストが終わらない・止まったときは、止まった原因を切り分けてから先へ進む。「環境のせいだろう」と推測で片付けない。確かめられないままコミットするなら、それは品質とのトレードオフなので、そう明言してユーザーに判断を仰ぐ。切り分けで作業を止める（stash など）なら、止めることと見込み時間を先に伝える。

**Why:** 2026-11-20 kurashi S29 で test_sounds が止まり、作業ファイルを stash して黙って待たせたうえ、待ち時間を指摘されると「止まっているだけ」と読んで未確認のまま push した。ユーザーから「品質とのトレードオフになっていないか」と問われた。

**How to apply:** 止まったら、まず止まった場所（出力・どこで待っているか）を見る。待つ・比べる・撤収のどれも、理由と見込みを添えて伝える。報告では、事実と推測を分けて書く。[[kurashi-test-cadence]] [[report-results-in-chat]]
