`misc/claude/kurashi/` は Python 標準ライブラリのみのローカルサーバ + ブラウザ UI の疑似生活アプリ
(2026-10-17 作成). リモートは https://github.com/function2706/comfy_life.git (main).
画像の同一プロンプト再利用は generatw の方式 (md5(pos+neg), 上限枚数まで裏で生成) に合わせた
([[generatw-adv-character-arch]]).

**実運用はこのPCではなく別PC.** このPCの 8765 は CipherCraftMail が使用中なので, 検証時は
`KURASHI_DATA=<scratchpad>` + 別ポートで起動し, `tools/mock_comfy.py --fail reject|exec|hang` で再現する.
push は Windows の git (GCM 認証済み) で通る. WSL の SSH 鍵は GitHub 未登録.

**Why:** ユーザーは別PCで動かしており, 不具合はこちらで再現・切り分けして push → 先方で pull の流れになる.
**How to apply:** 不具合報告は「生成ジョブ」パネルの経過ログ / data/server.log を貼ってもらって切り分ける.

ワールド別セーブ (2026-10-18 設計合意, 3段階で実装):
- 画像ファイルと画像索引はワールド間で共有. 定義類(コマンド/パラメータ/世界設定/出来事/働きかけ/ミニゲーム)はワールドごと.
  ComfyUI/LLM/表示の設定・性格プリセット・workflow は全体共通.
- 関係は a→b の向きごとに 認知(知る/知らない)+種類(自由記述)+好感度(数値, 出来事で変動).
- ①ワールド分割・移行・切替UI・関係データ ②ワールド開始時は誰とも暮らしていない. 登録キャラに連絡/会いに行く,
  関係が深まれば家に訪ねる/同居. 複数人と深い関係だと本命の心象が悪化(性格依存)
  ③お出かけ(一人でも誰かとでも)・仕事中に偶然知り合う. 未登録のランダムキャラとも出会い, 登録するか尋ねる(ランダム登録の機会はこれだけ).
  ランダム候補は「他ワールドの登録キャラ」+いなければ新規生成 (両方). 段階ごとにコミット/push して報告.
- 実装済み (2026-10-18): ① f9053ee ワールド分割 ② 03545bf core/bonds.py ③ e3c6538 core/encounters.py. 残: 離れている時の働きかけ(メッセージが来る)は未実装, 新キー以外の旧セリフは同居前提の文面が残る.
- ② の決定: 段階は しきい値+提案 (好感度/信頼を超えると「家に行っていい?」「一緒に住む?」が出て相手が性格と数値で可否).
  同居は一人だけ. 連絡は基本メッセージ(画像なし), 相手の気分次第で自撮り添付(テンションに応じた自然な頻度, 高すぎない).
  本命は各キャラが自分視点: あなたと仲が深いキャラそれぞれが他との深い仲を知ると嫉妬(性格で強弱, 同居相手は気づきやすい).

**公理: 現実的であること** (2026-10-18 ユーザー指示, b01043a で実装). 回数をこなせば仲が深まる作りにしない.
揺らぎ・その日の鈍り・繰り返しの逆効果・ご無沙汰で冷める・提案は断られうる・贈り物/お金は性格と仲しだい・偶然の出会いに補正なし.
**How to apply:** kurashi に新しい交流や効果を足すときは bonds.realize を通し, 確定的な上昇やしきい値だけで通る提案を作らない.

**キャラの定義と個体** (2026-10-19 ユーザー指示, d5a9cc2): 定義は全体で 1 つ (data/characters/, 編集は全ワールドに反映),
各ワールドは cast.json の顔ぶれ + 個体 (状態・ログ・間柄・関係). 削除は定義の抹消で, どこかのワールドに現れているキャラは削除不可 (変更は可).
「ワールドから外す」操作は作らない. **How to apply:** キャラまわりを触るときは store.all_characters / load_cast / worlds_with を使う.
