更新が止まる不手際を 11/21・11/22 と二度起こし、ユーザーに「ソースではなくあなたの方法の修正が必要」と言われた (2026-11-22)。

- 実機の場所・シェルはユーザーの言葉と貼られたプロンプトだけで決める。記録や推測で補わない (Desktop\comfy_life を勝手に足した。実機は最初から E:\BOX\その他\アプリ\application\comfy_life)。
- 実機で打つコマンドはターンの最後の本文にだけ書く (途中の文は届かないことがある)。シェルが不明なら git だけで書く。
- 確認 1 本 → 事実を見て直し 1 本。推測で直すコマンドを出さない。
- パッチ・急ぎの直しを届ける前に、実機が受け取れるか (CHANGES に書いた実機側の手作業が済んだか) を画面の版で確かめ、済んでいなければ同じ本文で先に手順を出す。
- 更新・起動まわりの直しは、実機の画面の版がそのコミット以降になったことを確かめてから終える。テストは本物の経路で。

**Why:** 11/21 に「止まっている実機は手で戻す」と書いただけで済んだか確かめず、11/22 の急ぎのパッチ (約束を 19:30 に戻す) が届かなかった。さらに誤った場所・シェル・届いていないコマンドで往復を重ねた。
**How to apply:** kurashi で実機に何かを届ける・復旧の手順を出すときは毎回これを通す。[[kurashi-prod-pc]] [[stalled-test-no-retreat]]
