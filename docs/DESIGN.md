# Comfy LIFE 設計書

機能を継ぎ足してきた結果, 仕様が README・説明書 (`static/manual.html`)・各モジュールの docstring・会話に散らばっているので, 「なぜそうなっているか」と「どこに何があるか」をここに 1 枚でまとめる。
細かい使い方は README と説明書, 実装の詳細は各モジュールの docstring が正。ここは全体の地図と方針。

## 1. 公理: 現実的であること・清濁併せ呑む

このアプリは「キャラと暮らしている感じ」を作るもので, ゲームとしての手応えのために現実味を曲げない。

- **回数や贈り物で必ず深まる作りにしない。** 好感度・信頼の上がり方は毎回揺らぎ, その日のうちに上がるほど鈍り, 機嫌が悪いと半減し, 同じことの繰り返しは逆効果になりうる（`bonds.realize`）。贈り物・お金は仲の浅さ・頻度・性格で喜ばれない／重いと断られる（`gift_feel` / `money_feel`）。交流が途絶えれば冷め, 家に行ける仲も遠のく（`cool_down`）。段階の提案は数値だけでなく最近の交流・ご無沙汰・性格・その日の気分で断られる（`readiness`）。
- **出会いに補正をかけない。** 知らない人に会いやすくする補正も, 誰かに必ず会わせる代わりもない。会わないまま何週間も過ぎてよい。
- **相手の状態は, 一緒にいるか本人が伝えたときだけ見える。** 離れている相手の場面・表情・機嫌の理由は画面に出さない（聞いた理由だけ。設定の `showApart` は開発・確認用）。メッセージは既読・返信の遅れ・来ないことで間接的にしか分からない。
  - 相手の所持金は, 離れていても同居していても画面に出さない。分かるのは, あなたが知りうること（貸し借りの額・生活費の分け方の取り決め・相手が口にしたこと）だけ。お金に困っているかは, おねだり・会話・部屋の様子からにじむ。
- **不便さや何も起こらなさは, このゲームの真髄として残す**（ユーザーの言葉）。手応えのために不便さを減らさない。「出かけても誰にも会わない」「返信が来ない」「予定どおりにいかない」は欠陥ではない。
  - ただし「その場では分からないが, 後から振り返れば分かる」手がかりを残すのは歓迎（例: 日記・時系列のまとめ・トークの既読に, 理由の痕跡がにじむ）。手がかりは答えを直接言わない。
- 良いことも悪いことも起きる（清濁併せ呑む）。キャラにも自分の生活と出来事があり, 機嫌はあなたの行動だけで決まらない。

新しい仕組みを足すときは「確率で必ず報われる道」を作っていないか, 「見えないはずのものを見せていないか」を最初に確かめる。

## 2. 全体の構成

```
server.py            HTTP サーバ / API (Python 3.8 標準ライブラリだけ)
static/              UI (素の JS) と説明書 manual.html
core/engine.py       App: 時間経過・場面・行動 (act)・プロンプト合成・生成キュー・state_view (画面の 1 回の更新. あなた中心)・
                     「誰かと」の相手 (target)・あなたの時系列 (timeline)・関係性 (people_view)
core/store.py        ファイル入出力・data/ の初期化と移行・移行前のバックアップ
core/cond.py         条件式 ("free=true, mood>=50, phase=night|midnight")
core/keys.py         セリフのキー (性格プリセットの差し替え用)
core/life.py         お金・株・仕事・スキル・体力, キャラの出来事・機嫌の理由・おねだり
core/presence.py     あなたの在席状態と, キャラからの働きかけ
core/bonds.py        あなたと各キャラの間柄・いまそばにいる人 (company)・現実的な深まり方・嫉妬・自撮り・あなたが知ったこと
core/solo.py         一人の時間・あなたの予定 (告げる相手なし)・日記
core/places.py       行き先の表 (公共の行き先 + あなたの家 + 知っている相手の家)・以前の表し方の読み替え
core/outdoor.py      外出の現在地・天気・出会いの起きやすさ・画面を閉じたときの切り上げ
core/street.py       出先でのばったり (誰に会うか・段階的に知り合う・反応)
core/encounters.py   知り合った人の登録 (と, 旧来の出会いの経路)
core/offline.py      画面を閉じていた間の, あなたの行動パターン
core/items.py        品物・持ち物・買うものリスト
core/chat.py         メッセージアプリ (トーク)
core/planner.py      あなたの予定 (日ごと. 閉じている間の過ごし方: 予定 → 未指定時コマンド → 行動パターン. 約束が先. 自動の応答)
core/posing.py       ポーズ・見せて (頼む・相手から・持ちかけと対価・感想・好みの学習. 大人のキャラだけ)
core/wardrobe.py     服の一覧と持っている服・大胆な服の受け入れ・服のプレゼント・本人の服選び・本人が服を買う
core/transfer.py     セーブの書き出し・読み込み (ワールド 1 つ + 顔ぶれの定義 + 任意で画像を zip に. 読み込みは新しいワールドとして足す)
core/home.py         あなたの家の状態 (散らかり・洗い物・洗濯物・ゴミ) と, 招いた相手・同居相手の反応
core/kakeibo.py      家計簿 (お金の出入りの裏の記録と, つけた分・見積もり)
core/body.py         あなたの体: お腹・栄養 (主食・たんぱく質・野菜)・食事 (自炊・外食・買って食べる)・体調
core/games.py ほか   ミニゲーム (麻雀・盤面・カード・花札・ヨット)
tools/test_*.py      テスト (一時データ). tools/simulate.py は長期シミュレーション
```

時間の進め方は 3 系統ある:

| 系統 | 何を | どこで |
|---|---|---|
| キャラの 5 分刻み | パラメータ (基本変化 + 場面の毎時効果 + 在席の効果 + 自然回帰)・日給と生活費・出来事・ご無沙汰で冷める・嫉妬 | `App.tick(cid)` → `_step` / `life.step` / `bonds.step` (最大 14 日ぶん追いつく) |
| あなたの 5 分刻み | 株の値動き（取引時間だけ）・ニュース・注文・積立（`market.step`）・日給・体力の回復 | `life.tick_world` |
| 画面を閉じていた間 | 行動パターンに沿った仕事・買い物・出会い・届いたメッセージ | `outdoor.check_gap` → `offline.simulate` |

`App.tick` は画面の更新のたびに, そばにいる人と連絡先を知っている人（と, 操作・返信の届いたキャラ）を進める。ほかのキャラは次に触れたときにまとめて追いつく（結果は同じだが, 14 日を超えた分は捨てられる）。

| `worlds/<w>/state/<cid>.json` | ワールド | キャラの個体の状態 (下表) |
| `worlds/<w>/log/<cid>.json` | ワールド | キャラとの出来事の記録 (画像・セリフ・効果) |
| `worlds/<w>/player.json` | ワールド | あなたの状態 (下表) |

キャラの状態 (`state/<cid>.json`) の主な項目: `params`・`override`（一時的な過ごし方）・`dress`・`cooldowns`・`last_interaction`・`money.a`・`events`・`reasons`（機嫌の理由）・`request`（おねだり）・`approach` / `ap_last`（働きかけ）・`gain_day` / `touch_days` / `last_touch` / `gifts`（現実的な深まり方）・`contacts`（連絡の回数）・`msg_pending`（返信の予定. 一つだけ）・`date_promise`（会う約束）・`peek_until`（電話中だけ様子が見える）・`jealous`・`lent`（あなたに貸したお金）・`last_met` / `last_contact`（最後に会った・連絡した）・`known`（あなたが知ったこと: 好き・苦手・聞いた話）。

あなたの状態 (`player.json`) の主な項目: `money`・`market`・`skills`・`stamina`・`work_log`・`presence`（在席・一人の時間・行き先・出先の記録・ばったりの返事待ち）・`bonds` / `with`（間柄・いま誰と一緒か）・`encounter`（登録を尋ねている人）・`items` / `shop_list`・`offline_report`・`appoints`（約束）・`debt` / `debt_t`（借金の残高・始まった時）/ `loans` / `loan_t`（誰にいくら借りているか・借り始め）/ `money_notes`（お金のできごと）/ `side_job_t`（最後に内職を終えた時刻. 休憩はあなたの記録）。

## 4. 主要な概念

### あなたが中心（何を・誰と）
画面と API は「選んだキャラ 1 人」ではなく「あなた」が中心。あなたの在席・一人の行動・お金・持ち物・スマホがいつもあり, そこに **いまそばにいる人たち**（`bonds.company()`）が加わる。
- そばにいる: 外で会っている・相手の家にいる・招いた人（`with`）と, 家にいる同居相手。同居相手は, あなたも相手も家にいるときだけ（`bonds.mode` / `home_together`: 在席が `out` / `work` か, 相手の場面が `away` なら離れている）。招いた人と同居相手が両方いれば二人。
- **そばにいる効果（寂しさが紛れる）は, あなたとその人の二人きりのときだけ**（`engine._step` の `bonds.alone_with`）。複数人いる中では, あなたへの寂しさは紛れない。
- 「誰かと」の相手（`App.target`）はそばにいる人から選ぶ。誰もいなければ None で, 画面の「誰かと」は出さず, ステージ（画像と会話欄）には何も出さない（画像は常にキャラクターのものだけ）。いまは一人に向けた行動だけ（二人同時に向けた行動・ほかの人が見ている反応は未着手）。
- 一人の行動（戻る・仕事から帰る・内職・株）は, そばに誰もいなければ誰も反応せず, 結果はあなたの記録（`App.my_entry` → mylog）。いれば, その人が反応する（いままでの `_back` / `work` など）。
- キャラのログに残すのは, その人がその場にいて関わった出来事だけ。あなた一人の行動はあなたの記録（mylog）にだけ（以前のデータで離れている相手のログに書かれていたものは, 起動時に移す）。
- 記録はあなたの 1 本の時系列（`App.timeline`）: 各キャラのログと一人の時間の記録を時刻順に並べ, 人で絞り込む。離れていたときの記録は `apart`（相手がそのとき何をしていたかは出さない）。
- 関係性（`App.people_view`）: 知っている人全員の間柄・最後に会った/連絡した・あなたが知っていること（`bonds.learn` / `remember`）・貸し借り。相手の所持金は出さない。
- 相手の予定（`core/knowsched.py`）: 遊んでいるあいだは分からない。話のついで・人づて・職場で見かける・メッセージで少しずつ分かり, 関係性に「火曜の夕方はスーパーでバイトしているらしい」の形で残る。聞いた話は古くなり, 予定が変われば外れる（聞いたときの中身と比べる）。スキルは聞ける頻度にだけ効き, 必ず聞けるわけではない。
- 以前の「選んでいるキャラ」（`settings.active_character`）は, 最後に選んだ「誰かと」の相手として残し, そばにいなければ使わない。`App.char(None)` は互換のためにそれを返す（API は相手を明示する）。データの移行は要らない（内職の休憩は以前のキャラの状態の記録も見る）。

### ワールドとキャラ（定義と個体）
定義は全体に 1 つ（`characters/`）, 個体（状態・ログ・間柄・関係）はワールドごと。ワールド A のひなと B のひなは別の日々を過ごす。定義の削除はどこにも現れていないときだけ。新しいワールドは誰とも暮らしておらず, 定義全員から「連絡先／知り合い／まだ知らない」をくじで決める（`encounters.start_cast`）。まだ知らない定義は, そのワールドでの出会いの候補になる。

### 在席状態（あなた）
`presence.mode`: none（here / idle は心拍と操作から）・busy・out・work・sleep・left, 心拍が途絶えれば gone。画面は 30 秒ごとに心拍を送る。外出 (out / work) は画面を開いている間だけ続き, 閉じたら最後の心拍で切り上げて家に帰った扱い（`outdoor.check_gap`）。寝る・離れるは閉じてもよい。黙って閉じると相手は寂しさが早く増え, 戻ると機嫌・信頼が下がる（`silent_penalty`）。

### 同時にできないこと
あなたは一度に一つのことしかしない。内職・一人の時間（休む・家事・研鑽）・誰かとのミニゲームの途中は, ほかのことを始められない（`App.blocked`。理由は押す前に出す）。外出・仕事・寝る・席を外す間は, 画面ごと切り替わっていてほかの操作はできない。

### 一人の時間・あなたの予定
`solo.KINDS`（休む・家事・研鑽・散歩・買い物・カフェ）は「始めて, 戻るまで」で, 戻ったときに過ごした時間で結果が出る（`solo.result`）。`solo.PLAIN`（作業・仕事・寝る・席を外す）は告げる相手がいなくてもできるあなたの予定。「作業する」は同居相手に作業中と伝えて遠慮してもらうためのものなので, 一人暮らしでは出さない。「席を外す」はそばにいる相手に告げて離れるためのものなので, 一人のときは出さない（一人なら画面を閉じればよい）。そばに誰かいれば, どちらも既存の `go_*` コマンドとして相手に告げる。

### 外出と行き先
行き先は 1 つの表（`core/places.py`）。公共の行き先 `PLACES`（近所: 公園・河川敷・駅前・街 / お店: 商店街・カフェ・スーパー・コンビニ・ドラッグストア・本屋・家電量販店・モール / 遊びに: 水族館・遊園地・海・山・星空の見える丘 / 職場。時間帯ごとの人の多さ・屋外か・そこでできること `does`・入場料）に, あなたの家と家に行ける仲の相手の家（`home:<id>`）が加わる（`Places.table()`）。
- 一人の外出は「外出」1 つ（`solo.KINDS["out"]`）で, 行き先しだいですることが決まる（`places.solo_kind`: 歩く・買い物・お茶・見て回る・訪ねる）。相手の家を選ぶと約束なしの訪問（`App.drop_in`: 留守・出てこない・迎えてくれる・断られる。仲・機嫌・慎重さ・時間帯しだいで補正なし）。
- 誰かとのお出かけはコマンドの `override.place`（選べるものは `places`）。`override.location` は表示用に行き先の名前。
- 行動パターンの外出は `do: out` + `place`。買うものリストの品は, 売っている店でだけ買える（`items.CATALOG.places`）。
- 以前の表し方（一人の時間の `walk` / `shopping` / `cafe`, お出かけの日本語の場所, 行動パターンの `do`）は読み替える（`solo.LEGACY`・`places.from_location`・`offline.normalize`）。設定の行動パターンは起動時に書き換える（`store.migrate_routine`. 移行前に自動バックアップ）。
- 営業時間（`places.HOURS`）: お店・遊び場には開く・閉まる時刻と定休日・季節がある（公園・河川敷・駅前・街・コンビニ・丘・家はいつでも. 夜は人がいないだけ）。閉まっている行き先は選べず, いる行き先が閉まれば出される（`outdoor.closing`）。約束は会う時刻に開いていること, 行動パターンの外出は閉まっていれば行かない。相手の家は営業時間ではなく在宅・時間帯で決まる。
- 天気はリアルの日付から決まる。

### 偶然の出会い・顔なじみ・段階的な知り合い
外出中, 心拍のたびに `outdoor.live` が起きやすさ（行動 × 行き先の人の多さ × 天気. 補正なし）で判定し, 中身は `street.happen`。人ごとに「よく行く場所と時間帯」（`haunts_of`, 名前と外見から決まる）があり, 同じ場所・時間帯に通えば同じ人にまた会いやすい。未登録の人は `people.json` で「まだ知らない → 見かけた → 会釈 → 立ち話 → 知り合い」と進み（こちらの反応 × 相手の caution × 偶然）, 知り合いになると登録（連絡先の交換）を尋ねる。仕事中は同僚だけ。返事をしないまま時間が過ぎると, 無難に会釈して流したことになる。

### 約束（アポ）
同居していない相手とは, 約束してから会う（`core/appoint.py`。約束なしのお出かけ・訪問・招待はできない）。こちらから日時 × 行き先 × 何をするかで誘い（返事は時間差. その時間の相手の予定・仲・機嫌・慎重さしだい）, 相手からも誘われる（仲・寂しさ・性格・その日の気分しだい, 補正なし。行き先は好みと思い出で気持ち傾くだけで, 性格で決め打ちしない）。誘われたら, 受ける・断るのほかに「別の日時なら」と返せ, 相手は受ける・断る・さらに別の案を返す（3 回まで）。こちらからの誘いを断るときにも, 相手から別の日時が返ってくることがある（予定が合わないだけなら返しやすく, 仲・機嫌・性格しだい）。当日の相手の側（すっぽかし・遅刻）は約束したときに決まっていて見えない（性格の `punctual`・仲）。体調不良のキャンセルは当日の健康しだい。当日は自分で約束の場所へ出向く（ふつうの外出。約束の場所にいる状態で時刻を迎えると会える。早く着けば待つ）。約束の時刻にいなければ遅刻, 45 分いなければ（画面を閉じていても）すっぽかし。画面を開いている間も出向くのは手動（行動パターンには沿わない）。移動時間は, ほかの外出と同じく入れていない。記録は `player.json` の `appoints`。統一モデルでいえば「共有する未来の Activity」の最初の形（手順 4 の一部）。

### 出先での合流・互いの家
一人で出かけて連絡先の相手と立ち話をしたら, そのまま一緒に過ごす話になることがある（相手から誘う / こちらから誘う。どちらも仲・機嫌・寂しさ・性格しだいで, 断られることも. 補正なし）。合流したら一人の外出はそこまでで, 相手は同じ行き先の一時シーン（`with.mode = meet`）。外で会っている家に行ける仲の相手とは, 互いの家へ（`bring_home` / `go_her_home`）。相手の家では暮らしぶり（`places.home_glimpse`）が, あなたの家では家の様子への反応（`home.on_guest`）がある。

### 間柄の段階
`bonds.STAGES`: known（知り合い. 連絡先を知らない）→ contact（連絡先）→ visit（家に行ける仲）→ live（同居. 一人だけ）。いまどこで誰といるかは `with`（None = 自分の家, meet = 外で会っている, visit = 相手の家, guest = 相手をあなたの家に招いている）。一緒にいない相手には「連絡・会う・あなたの予定」とお出かけの誘いだけ（`allowed_apart`）。段階の提案は `ready` 条件で受けるかが決まる。ご無沙汰（`drift_apart_days`）で visit は contact に戻る。

### メッセージ・電話
離れている相手へのメッセージは送るだけで, 返信は `msg_pending`（数分〜40 分. 機嫌・好感度で遅れる・来ない）。寝ている・手が離せない相手には落ち着くまで届かない（`deliver_due`）。トーク（`chat.py`）は送る種類 × 状況で返信が変わる（夜中・連絡しすぎ・理由を知らずに謝る・浅い仲で甘える など）。「会おう」に応じてくれると半日の `date_promise`。相手が送った・返した直後はしばらくスマホを見ていて（`phone_until`）, その間に返すとすぐ返ってくることもある（`_still_on_phone`. 機嫌・好感度・続いた回数・性格しだいで, 必ずではない）。電話は出ないことがあり, 折り返しがメッセージで来ることも。連絡しすぎ（`too_often`）や仕事中の連絡は響く。

### キャラからの働きかけ
一緒にいるときは寂しさ・退屈・好感度に応じて話しかけてくる（`approaches.json`）。離れている相手からは `"apart": true` のものだけがメッセージとして届く。返事は選択肢から選び（`core/msgreply.py`）, どれが良く効くかは性格・機嫌・仲・内容しだいで揺らぐ（返事をすれば必ず良くなる, ではない）。返事をしないと「返事がなかった」になり, 寂しいとき・既読のまま放っておいたとき・急ぎの内容ほど機嫌が下がる（気にしない性格もいる）。

### あなたの予定（日ごと）
「一人で」タブの「予定」で, 閉じている間の過ごし方を日ごとに組む（`core/planner.py`）。決まる順番は 予定 → できなければ未指定時コマンド（優先度順）→ 設定の行動パターン → 何もしない。約束の時刻は約束が先。画面を開いている間は知らせるだけで何もしない（不便さを減らす自動化にしない）。閉じている間の自動の応答・約束は, 手でするより効き目を弱くし, 読み違えもある（公理: その場にいないことの不利を残す）。

### オフラインの行動パターン
`settings.offline.days`（曜日ごとの `[{at, do, place?, skill?}]`）。画面を閉じていた間はこれに沿って過ごしたことにする: 仕事（早退・叱られる・残業）・買い物・散歩・カフェ・家事・研鑽（一人の時間と同じ結果）・予定どおりにいかないこと（雨で散歩をやめる・疲れて飛ばす）・出先や職場での出会い（気づけないので無難な対応）・届いたメッセージ（すぐ返せないことの受け止め方は性格と信頼しだい）。結果は `offline_report` で一度だけ見せる。

### 持ち物と買い物
`items.CATALOG`（値段・売っている行き先・種類・好みの印・プレゼント可否）。買い物では買うものリストの品がその店にあれば買う（品切れ・値段の上下・お金しだい・衝動買い）。料理=食材・お茶=お茶っ葉・おやつ=お菓子・家事=洗剤を使い, 無ければ効き目が落ちる。研鑽は本があると伸びやすい（減らない）。プレゼントは持ち物から。

### 自宅の状態
`core/home.py`。散らかり・洗い物・洗濯物・ゴミがそれぞれ 0〜100 で, 家にいて起きている間がいちばん早くたまる（寝ている・出かけている・画面を閉じている間はゆっくり. 同居相手・来客がいれば早い. 料理で洗い物, 来客のあとは少し散らかる）。家事（一人の時間・行動パターン. 洗剤があるとはかどる）と「一緒に掃除」で片付く。招いた相手（「うちに来ない？」→ `with.mode = guest`）は来たときの家の様子に, 同居相手は日々の家の様子（一日に一度ほど, 気づいたときだけ）に反応する。反応は性格の `neat`（きれい好き）・`carer`（世話焼き）しだいで, 片付いていても気づかないことがあり, 散らかっていても気にしない人・片付けを手伝い出す人もいる（好感度・信頼の動きは `bonds.realize` を通す）。旧来の「家事に気づく」は `home.notice_chores` に統合した。トップバーの 🏠 の札から確かめられる。

### 食事と栄養（あなた）
あなたにもお腹と栄養（主食・たんぱく質・野菜の 3 つ, 数日分の蓄え）がある。食べ方は自炊（食材と料理スキル）・外食（店と営業時間）・買って食べる。手間とお金と栄養が釣り合わないのは公理どおり（自炊は安くて栄養がそろうが食材の準備と腕が要る, 外食は手軽だが高い, コンビニは手軽で安いが偏る）。オフラインの行動パターンにも食事を置け, 置いていなければ食べない（不便さは減らさない）。見えるのは自覚できる言葉だけ。

### 運動（あなた）
数日分の体を動かした量。歩く外出・ジョギング（一人の行動）・誰かとのお出かけ・家事で満たされ, 足りない日が続くと体力の上限・回復・体調に響く。家にこもる暮らしは不利になるが, それも暮らし方の一つとして減らさない。

### 体調（あなた）
栄養の偏り・寝不足・働きすぎ・空腹・運動不足・雨雪・冬が重なると, 日付が変わるときに体調を崩す（段階: 軽い不調・風邪・寝込む）。崩しやすさも治りやすさも過ごし方しだいで, 必ず崩す・必ず治る道はない（公理）。休めば治ることが多いが, 無理を続ければこじれる。薬と病院はお金がかかる。体調が悪い間は体力・給料・スキルの伸びが落ちる。そばにいる人は顔色に気づくことがあり, 応じれば看病してくれる（`worry_you`）。

### 家計簿
お金の出入りは裏ですべて記録し（`ledger.raw`）, 見えるのは家計簿につけた分（`ledger.book`）だけ。公理どおり, 記録をつけなければ何にいくら使ったかは分からず, 日を空けるほどうろ覚えになる（丸まる・まとまる・書き漏らす）。見積もりは, 決まっている固定費と, 記録からの変動費（記録が少ないほど幅が広い）。財布の残高はいつでも見える。

### お金・スキル・体力
あなた: 仕事（時給 × 給料の出る時間 × 仕事スキル. 6〜23 時・1 日 9 時間まで。時給は月ごとの勤務で見直し, 6・12 月に賞与）・アルバイト（シフト制）・副業（スキルを生かした依頼. 運と評判しだい）・頼まれごと（知り合いから. お礼は仲しだい）・フリマ（品物と時期しだい）・宝くじ（ほぼ当たらない）・内職・株・わずかな日給。どれも「やれば必ず稼げる」作りにしない（依頼は来ないこともあり, 出来ばえは揺れ, 売れ残り, 外れる）。キャラ: 日給と出来事。
暮らしのお金は家ごと（`life.pay_home`）: あなたが払うのはあなたの家の分だけで, 毎日の生活費（一人なら二人暮らしの半分）と月はじめの家賃・光熱費・通信費。同居相手とはその人の方針（折半など）で分け, 一緒に暮らしていない人は自分の生活費を自分で払う。足りなければ連絡先の人に借り（`borrow`. 頼む相手・断られるか・印象の変わり方は間柄・仲・性格・懐具合しだい）, 借りられなければ借金。借金のあいだ（`life.in_debt`: 借金か借りたお金が残っている）は必需品（食材・洗剤）しか買えず, 借金には月はじめに少し利息がつく。お金があるときに返せる（`repay`. 相手に返すと信頼が少し戻る）。事情を知っている相手（貸した人・同居相手）は, 返すのが遅いと心配したり不信感を持ったりする（`money_concern`. 性格・仲しだい, 不信感は口に出さないことも）。取り立てはない。スキル（会話・スキンシップ・料理・仕事）は使うほど・研鑽で伸び, 効き目（仕事は給料）を 0.6〜1.4 倍にする。数か月かけて少しずつ上達する速さ（`life.train`: 経験の `SKILL_RATE` 倍だけ身につき, 上がるほど・同じ日にたくさんやるほど伸びにくい。得意・不得意 `aptitude` とその日の調子で揺れ, 伸びない日もある）。体力は仕事・内職・外出・家事で減り, 時間で戻る（寝ると早い）。減っていると構っても効きが悪い。

### 性格の traits
性格プリセットの `traits`: `rate` / `drift` / `drift_speed`（パラメータの動き方）・`gain` / `hurt`（うれしい／つらい方向の効き目）・`approach`（話しかけてくる多さ, 連絡の許容, ばったりで声をかけてくる多さ）・`absence`（黙って離れられたときの堪え方, 返事の遅れ）・`jealousy`・`caution`（段階の提案・連絡先の交換・顔なじみの進み方）・`gift` / `money`（贈り物・お金の受け止め方）・`modesty`（恥じらい. 大胆な服への抵抗. 控えめに効かせる）。セリフ（`lines`）は口調だけを変え, 条件・効果は共通。

## 5. 重なっている概念

同じことを別々の仕組みで表しているところ。今すぐ壊れてはいないが, 機能を足すたびに全部を触る必要があり, 食い違いの温床になる。

| 何 | 別々の表し方 |
|---|---|
| あなたが「何をしているか」 | `presence.mode`（busy/out/work/sleep/left）＋ `presence.solo.kind` ＋ `presence.place`, `solo.KINDS` / `solo.PLAIN`, `go_*` コマンド（`presence_set`）, `offline` の `do`（sleep/rest/home/work/out/chores/practice）。同じ活動に 3〜4 通りの語彙がある（外出は「外出 + 行き先」にそろえた） |
| 外出していること | あなたの out / work, キャラの `override.outing`（誰かとのお出かけ）, `bonds.with.mode = meet`, キャラのスケジュールの `away`。`outdoor.current` がこれらを寄せ集めて現在地を推定している |
| 行き先 | 表は `core/places.py` 1 つにした（一人の外出・お出かけの `override.place`・行動パターン・品ぞろえ・家）。残っているのは, キャラのスケジュールの `location`（自由記述. 出会いとは無関係）と, 顔なじみの習慣 `street.HAUNT_PLACES`（名前から決まるので, 既存の人の習慣が変わらないよう以前の 6 か所のまま） |
| 誰と一緒か | `bonds.with`（あなた側の 1 枠）, 同居（`stage = live` で, あなたも相手も家にいれば一緒）, 誘ったお出かけの `override`（キャラ側）。`bonds.sync` が両者を合わせ, `bonds.company()` がまとめて「いまそばにいる人たち」にする。同時にそばにいられるのは, いまは「会っている・招いた人 1 人 + 家にいる同居相手」まで |
| 出会い | 現行の `outdoor.live` → `street.happen`（起きやすさは `world.outdoor.rate_*`）と, 旧来の `encounters.happen` / `roll` / `bump` / `meet_stranger`（`world.encounters.rate_*` / `stranger_share`）。後者は `/api/encounter/force` とテストからしか呼ばれず, `roll` は使われていない |
| 「知り合い」 | 未登録の人の段階 `street.STAGES[4]`「知り合い」（ここで登録を尋ね, 登録すると contact）と, 登録キャラの `bonds` の known「知り合い（連絡先を知らない）」 |
| 交流した記録 | `last_interaction`（engine）, `last_touch` / `touch_days`（bonds）, `contacts`（連絡の回数）, `ap_last`, `gifts` |
| 何があったかの記録 | キャラごとの `log`, `mylog`, `presence.street_log`, `offline_report.timeline`, トーク, 日記, `reasons` / `events`。画面のログは `App.timeline` で `log` と `mylog` を 1 本に並べている（保存は別々のまま） |
| 「そばにいない」と「出かけている」 | `context()` は離れている相手について, あなたから見て「そばにいない」ことを `away=True` で表す。以前は同じ `away` がその人自身のパラメータの規則（退屈が減る・ストレスの目標 +25・元気が速く減る）にも効き, 家にいても「ずっと外出中」の体の動きになっていた。いまは本人の動き・出来事は `context(..., view=False)`（本人の予定どおり）で分けている。条件式のキー `away` 自体は, まだ「見えない」と「出かけている」の両方の意味で使われている（統一モデルで分ける） |
| 体力の回復 | `life.tick_world`（在席から推定）と `offline.simulate`（行動パターンから計算し直して上書き） |
| 返信の予定 | `msg_pending`（1 枠. 送るたびに `count` と `kind` を上書き）。働きかけの返事待ち `approach` も 1 枠 |
| 効き目の掛け算 | コマンドの効果 × `repeat_scale` × スキル × 体力 → `bonds.realize`（揺らぎ・鈍り・機嫌・繰り返し・贈り物）→ `trait_effects`。層が多く, 最終的な効き方が読みにくい |

## 6. 今後の方向: 「いつ・どこで・何を・誰と」の統一モデル（案. 未実装）

あなたもキャラも, 時間の区間ごとに 1 つの **活動** で表す:

```
Activity = {
  who:   "player" | <cid>,          # 誰の活動か
  t0, t1,                           # いつ (t1 は予定. 戻るまで続くものは None)
  do:    "sleep" | "home" | "rest" | "chores" | "practice" | "work" | "walk" | "shopping" | "cafe" | "outing:<id>" | "visit" | ...,
  place: "home:<who>" | "park" | "cafe" | "office" | ...,   # 行き先 (PLACES の id か, 誰かの家)
  with:  [<cid>, ...],              # 同行者 (誘った/誘われた/合流した)
  said:  true/false,                # 告げてから始めたか (黙って閉じた = gone)
  src:   "screen" | "routine" | "schedule" | "invite" | "promise",   # 何から決まったか
  result: {...}                     # 終わったときの結果 (稼ぎ・買ったもの・出会い・スキル)
}
```

- あなたの在席 (`presence.mode`)・一人の時間 (`solo`)・行動パターン (`offline.days`)・外出 (`outdoor.current`)・誰かとのお出かけ (`override.outing` + `with`) は, すべて「いまの Activity」と「予定の Activity 列」に読み替えられる。
- キャラのスケジュールも Activity 列にすれば, キャラも実際に「どこかにいる」ことになり, 出先での合流（同じ place・同じ時間帯にいる人に会う）や約束（未来の Activity を二人で共有）が自然に書ける。`haunts_of` は「その人の Activity 列の傾向」に吸収できる。
- 出会いは「同じ place に同時にいる Activity どうし」で判定でき, 補正なしの公理とも合う。
- 記録（log・mylog・street_log・offline timeline）は「終わった Activity と, その間に起きたこと」として 1 本にでき, 日記の「後から振り返れば分かる」手がかりもここから作れる。

### 移行手順（段階ごとに動く状態を保つ）

1. **語彙をそろえる**: `do` の語彙を 1 つの表（`core/activity.py` の `DO`）にし, `solo.KINDS` / `PLAIN` / `offline.DO_LABEL` / `presence.MODE_LABEL` をそこから作る。行き先の id も `PLACES` 1 つに寄せ, お出かけのコマンドには `place` を持たせる（`override.location` は表示用に残す）。データ形式は変えない。
   - **済み（行き先）**: 行き先の表は `core/places.py`（家を含む）。一人の外出は「外出 + 行き先」, お出かけは `override.place`, 行動パターンは `do: out` + `place`。`do` の語彙の表（`core/activity.py`）はまだ。
2. **読み出しを Activity にする**: `activity.current(who)` / `activity.at(who, t)` を作り, `outdoor.current`・`presence.at`・`bonds.mode` の判定をそこ経由にする。保存は今のまま（読み替えだけ）。テストは今のものが通ること。
3. **あなたの側の保存を Activity にする**: `player.json` に `activity`（いま）と `plan`（予定）を持ち, `presence.mode/solo/place` と `with` をそこから導く。起動時の移行（`store` の移行 + 自動バックアップ）で旧項目を読み替える。`offline.simulate` は「予定の Activity 列を過ぎた分だけ実行する」になる。
4. **キャラの側**: スケジュールと `override` を Activity 列として扱う（定義の `schedule` はそのまま, 個体に `activity` を持つ）。ここで出先での合流・約束（共有する未来の Activity）を実装する。
5. **記録を 1 本に**: 終わった Activity を `W/activities.json` に残し, mylog・street_log・offline timeline をその表示に置き換える（旧ファイルは読むだけ残す）。
6. 旧来の出会いの経路（`encounters.roll` / `happen` / `bump` / `meet_stranger` と `world.encounters.rate_*`）を, 強制発生の API ごと `street` に寄せて消す。

各段階で: 新しい場面（セリフのキー）が増えるなら 8 章の手順, データ形式が変わるなら移行と自動バックアップ（`store.pending_migrations` に足す）, `tools/simulate.py` で推移が変わっていないかを見る。

## 8. 開発の手順

- **新しい場面（セリフのキー）が増えたら**: まず実装を **共通のセリフだけで** コミットする（`LINES` などの既定）。性格別のセリフは, 書く前に **追加予定数（場面数 × 性格数）をユーザーに報告** し, 了承を得てから **別コミット** で足す（ユーザー指示）。書いたら `python tools/check_persona.py`。
- 既定の `actions.json` / `minigames.json` / `events.json` / `approaches.json` を変えたら, コミット前に `python tools/build_default_history.py`。
- **データ形式を変える移行**は `store` に置き, 起動時に済んでいなければ `store.pending_migrations` に理由を足す。移行の前に `store.backup(理由)` が `data_backup/<日時>/` へ写す（画像は索引だけ, 一回の起動で一度だけ, `BACKUP_KEEP` 世代）。移行は途中で止まっても再開できるように（`_retire` / `_done` の印）。Windows では改名・置き換えが一時的に失敗することがある（`store.save` の再試行, `test_migrate_locked`）。
- 公理に関わる変更は `tools/test_realism.py` に足す。数値の推移は `python tools/simulate.py`（一人暮らし / `--start live`, `--seed`）で確かめる。何も起きない時間が長いのは仕様。
- テスト: `tools/test_*.py` を全部。`test_reuse_dress` と `test_comfy_output` は `python tools/mock_comfy.py --port N` を起動して `--comfy-port N`。日時に左右されるテストは `tools/testclock.py` で日曜の昼に固定する。
- 複数のセッションが同じフォルダで作業することがあるので, コミット前に `git status --short` で入れ忘れ・他人の作業の巻き込みがないか確かめる。コミットメッセージは 1 行目英語・2 行目以降日本語。

### 3 回目（2026-10-21, スキルの伸び方を直したあと）

`life.train` を見直した。1 回の経験（会話コマンド 1.2・仕事 1 時間 0.5・研鑽・内職など, 呼ぶ側の量はそのまま）のうち身につくのは `SKILL_RATE`（0.4）倍。上がるほど伸びにくい形は `(1 − 値/100)^1.5` で, 以前の `(1 − 値/110)` より強く効く。同じ日に伸びた量で割る（`SKILL_DAY_SOFT` = 2）ので, 一日に詰め込んでも伸びは頭打ちになる。揺らぎとして, 得意・不得意（`aptitude`: ワールドごとにスキルごと 0.7〜1.3 倍, 最初に使ったときに決まる）と, その日の調子（スキルごとに日替わりで 0.5〜1.3 倍。15% は 0.1 倍で, ほとんど伸びない日）を掛ける。給料の倍率（`skill_mult` = 0.6 + 値/100 × 0.8）は変えていない。

その後, スキルを 8 つにした（家事・気配り・身だしなみ・やりくりを足した。伸び方・鈍り・得意不得意・その日の調子は同じ）。新しい 4 つの効き目は控えめで（`life.skill_soft`）, 高くても結果は決まらない。やりくりを株のニュースの読みに効かせないのは, ニュースの当たり外れは誰にも読めないのが現実で, スキルで当たりやすくするのは補正になるから。4 週間のシミュレーションでは, ランダムな「あなた」はあまり使わないので 10 → 11〜15（家事・やりくりは家事・家計簿・買い物で少しずつ）。
