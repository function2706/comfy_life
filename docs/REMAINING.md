#### A17 設計（11/14。コードは未着手）

**要点**: 予定の形式（定義の `schedule` の 1 行 = `days / from / to / activity / label / asleep / away / busy / workplace …`）は変えない。型は「その `schedule` を作る元」として定義に足すだけにする。こうすると `engine._base_scene`・`rhythm`・`knowsched`・`appoint._alt_time` など `schedule` を読んでいる所（12 モジュールほど）はそのまま動く。

**1. 段の切り方**（機能追加 2 版。段 1 と段 2 は同じ版に入れる）

| 段 | 中身 | 版 |
|---|---|---|
| 1 | 型の表・予定の生成・`generate` の差し替え・定義の移行・知っている予定を消す・夜勤まわりの `rhythm` の手当て | 同じ版（minor） |
| 2 | 決まっている約束の点検と、相手からの打診 | 段 1 と同じ版（コミットは分ける） |
| 3 | 日締めの収支（収入・出費）と、所持金の効き先 | 次の版（minor） |

- 段 1 と 2 を同じ版にする理由: 予定を作り直した瞬間に約束が食い違うので、点検は同じ起動で一度に済ませる（間が空くと、仕事中の時刻の約束がそのまま成立してしまう）。
- 段 3 は遡及が要らない（収支の決め方が変わるだけ）ので、あとから安全に足せる。
- セリフ: 段 1・2 は新しいキーなし（既存の `appoint_move_mine` などを使う）。段 3 は「今月きびしい」の断り・割り勘の申し出で新しいキーが要る（27 性格ぶん。別コミット、書く前に行数を報告）。

**2. 型のデータの形**

- 型の表は新しい `core/lifetype.py` の `TYPES`（コード側。ワールドの定義類にはしない）。

```
TYPES[id] = {
  label,                      # 会社員 など（画面には出さない。knowsched の文面は schedule の label から）
  weight, age: (lo, hi),      # くじの重みと、合う年齢（学生は若い側だけ）
  work: {days: 決め方, n: 週の日数, slots: [(from, to), …], workplace: 行き先の種類の候補 or None},
  sleep: (起きる, 寝る),      # 型の基本。夜勤は昼に寝る
  extra: [授業・通学・習い事などの枠],
  free:  [休みの日の枠の候補（趣味・買い物・出かける）と重み],
  pay:   {kind: monthly / hourly / irregular, 倍率, 給料日, 賞与の月},   # 段 3
  cost:  {住まいの倍率, 暮らしの倍率},                                   # 段 3
}
```

- 型: `office`（平日 9〜18）/ `shift`（週 4〜5 日・曜日は人ごと・早番と遅番）/ `night`（22〜翌 6、昼に寝る）/ `student`（平日の授業 + 夕方か週末のバイト）/ `freelance`（家で仕事・時間は人ごと・夜型寄り）/ `service`（土日が仕事・平日 2 日休み）。
- 定義（`characters/<id>.json`）に足す項目:

```
"life": {"type": "shift", "v": 1, "src": "lottery" | "text" | "given" | "custom",
         "seed": "<定義の id>", "chrono": 45,          # 寝起きのずれ（分。+ が夜型）
         "off": ["tue", "wed"], "slot": 1, "workplace": "supermarket"}
```

- `schedule` は `lifetype.build(char)` が `life` から作る（同じ `life` なら同じ予定。くじは `seed` から決め、移行が途中で止まってやり直しても同じ結果）。
- 型の決め方（順に）: ① `life` がすでにある → そのまま。② 性格の文（`persona`）に職の言葉がある（大学生・会社員・看護・店員・在宅 など）→ その型（`src: text`。文面と食い違わせない）。③ 年齢で絞った重みつきのくじ（`src: lottery`）。
- 寝起きのずれ `chrono`: 性格の traits に `chrono`（−1 朝型〜+1 夜型）を足し（27 性格、数値だけ）、× 60 分 + 人ごとの揺らぎ ±30 分。型の仕事に間に合う範囲で止める（会社員が 9 時を過ぎて起きる予定にはしない）。日ごとのずれ（`rhythm`）はこの上にそのまま乗る。
- 勤め先 `workplace`: `shift` / `service` / `student` のバイトは店のある行き先から選び、勤務はその店の営業時間の中に収める（`places.HOURS`）。`office` / `freelance` は付けない。`night` はコンビニか、付けない（工場・病院などは label だけ）。
- 日をまたぐ枠（夜勤・夜型の睡眠）は、いまの睡眠と同じく 0:00 で 2 行に割って書く（後半の行に `cont: true`）。`day_match` は見ている時刻の曜日で引くため。
- シフトの曜日は人ごとに違うが、週ごとには変えない（「火曜の夕方はバイトらしい」が成り立たなくなるため。週替わりはやらない）。

**3. 既存ワールドの移行と遡及**

- 定義は全体に 1 つなので、移行は二層に分ける。
  - **定義（全体・一度）**: `store.pending_migrations` に「`life` の無い定義がある」を足す（自動バックアップのあと実行）。元の予定は定義に `schedule_old` として残す（戻せるように）。
  - **ワールド（ワールドごと・開いたとき一度）**: `player.json` に `life_v: 1` の印。開いていないワールドは、次に開いたときに同じ処理。
- 定義ごとの扱い:
  - ひな（既定の定義）: 予定は手書きで性格の文とも合っている（大学生・本屋のバイト）ので**そのまま**。`life = {type: student, src: given}` だけ付ける。
  - 予定がひなの既定と同じ（`generate` の写し・ひな型のまま）か空: 型を決めて作り直す。
  - それ以外（手で書き換えた予定）: **作り直さない**。`src: custom` とし、型は仕事の枠の時間から近いものを当てる（段 3 の収入のためだけ）。← 残件の「全員作り直す」から外した判断。手で作った予定を黙って捨てないため。
- ワールドごとの処理:
  - 知っている予定を消す: 作り直した人の `known` のうち `kind: schedule` と `sched_told`。予定を変えていない人（ひな・custom）は消さない。
  - `st.rhythm`（覚えた日ごとのずれ）を消す（その日から決め直し）。`rhythm_since` はそのまま。
  - 登録を尋ねている途中の人（`player.encounter.char`）も予定の写しを持っているので、同じく作り直す。未登録の顔なじみ（`people.json`）は予定を持たないので何もしない。
  - 約束の点検（4.）。
  - あなたの記録（mylog）に一度だけ「みんなの暮らしぶりが変わったようだ」を残す（同居相手の在宅の時間も変わるため、黙って変えない）。
- 遡及しないもの: 所持金（5.）、間柄・好感度、顔なじみの習慣（`street.haunts_of`。名前と外見から決まるまま）。
- これから作る人: `encounters.generate` はひなの予定を写すのをやめ、`life` を決めて `build` する。定義の編集で新しく作った人は、保存のときに `life` が無ければ付ける。

**4. 約束の打診**（段 2）

- 対象: `appoints` のうち、これから先の、予定を作り直した人との約束。
- 都合の判定: 約束の時刻から 2 時間のあいだに、新しい基本の予定（`_base_scene`。日ごとのずれは見ない）が `away` / `busy` / `asleep` なら「都合がつかない」。
- 状態ごと:

| 状態 | 都合がつく | 都合がつかない |
|---|---|---|
| `set` / `waiting` | そのまま | 相手から別の日時を打診（下） |
| `offered`（誘われて返事待ち） | そのまま | 同じく打診し直す（黙って時刻を変えない） |
| `asked`（こちらの誘いの返事待ち） | 何もしない | 何もしない（返事は返すときの予定で決まるので、新しい予定で自然に断る・別案になる） |
| 頼まれごと（`favor`） | 何もしない | `fixed`（留守の水やりなど）は触らない。会って渡すものだけ `favor_resched` の流れ |

- 打診は既存の「自分の都合で日を動かしたい」（`appoint.live` の `plan.move` → `appoint_move_mine`）をそのまま使う: `x.update(t=alt, status="offered", by="her")`・トークに一言・`her_moved`。受ける・断る・別の日時は、いまの返事の流れ。
  - `rounds` は増やさない（移行のせいでやりとりの回数を減らさない）。
  - `her_moved` は数える（相手が動かした事実。あとであなたが動かすときに「お互いさま」で通りやすくなる = 損の補償にもなる）。
  - 別の日時: まず `_alt_time`（近い日のくじ 12 回）。夜勤などで見つからなければ、先 7 日を順に探す。それでも無ければ、相手からの取りやめ（あなたへの悪影響なし）。
  - 送る時刻: 移行の瞬間に全員から一斉には来させない。約束に `plan.relife = true` を付け、`live` が「相手が起きていて手が空いている時刻」に人ごとに 5〜90 分ずらして送る。約束まで 3 時間を切っているものはすぐ。1 時間を切っているものは打診せず、そのまま来る。
- 当日の相手の側（すっぽかし・遅刻）は約束したときに決めた `plan` のまま（決め直さない）。
- 制限: `appoint.live` は画面を閉じている間は進まない（A16 の残り）ので、打診が届くのは家の画面を開いているとき。

**5. 所持金の収支**（段 3）

- 一日のシミュレートは新しい仕組みを作らず、いまの「予定の場面 + 日ごとのずれ」をその人の一日とみなし、**日付が変わるときの日締め**（`life.step` のいまの収入・生活費の所）で収支を出す。
- 収入: その日に実際に働いた分（予定の仕事の枠 + 残業 − 風邪で休んだ日）から。
  - `monthly`（会社員・夜勤・サービス業）: 給料日にまとめて。休んだ日は引く。賞与の月あり。
  - `hourly`（シフト・学生のバイト）: 働いた時間ぶんを月に一度。学生は仕送りが月はじめに。
  - `irregular`（在宅）: 月ごとに大きく揺れる（少ない月・入らない月もある）。
- 出費: 住まい（月はじめ。一人暮らしの人だけ。同居相手はいまどおり `pay_home` で分ける）・暮らし（毎日）・買い物と交際費（日ごとのくじ。給料日のあとは多め、月末は少なめ）。使い方の荒さは性格の `savings` を主に使う（残件の文は `money` だが、`traits.money` は「お金の受け止め方」なので、浪費・倹約には合わない）。
- 釣り合いの目標: **全員の平均は、いまと同じ（月に +3 万円ほど貯まる）**。足すのは型ごとの差と月の中の波だけ。金額は倍率で持ち、`tools/simulate.py` で型ごとに 90 日流して決める。いまの `econ.her_daily_income` / `her_living_cost_per_day` は倍率の基準として残す。
- 足りないとき: 0 円で止める（キャラの借金は作らない）。いまの「生活費が苦しい → ストレス・機嫌」はそのまま。残高が暮らし 10 日ぶんを切ったら「苦しい」（`st.money.tight`）。
- 決め方は「人 × 日付」から決まるくじにする（その場で進めても、まとめて追いついても同じ結果）。14 日を超えて追いつけなかった分は、日数 × 平均でまとめて足す（いまは捨てられている）。
- 初めの所持金: 新しく現れる人は、いまの `her_start_money`（性格の `savings` × 揺らぎ）に型と年齢の倍率を掛ける。**既存の人の所持金は変えない**（貸し借り・おごりの経緯が乗っているため。← 残件の「型と年齢から決める」は新しい人だけに当てる判断）。
- 相手の所持金は、いままでどおり画面に出さない。分かるのは振る舞いと一言だけ。

**7. テストで確かめる点**

- 段 1
  - 型 × 性格（27）× 種 20 個の総当たり: 予定に重なりと抜けが無い（24 時間 × 7 日を 5 分刻みで引いて、どの時刻も場面が 1 つ）／ 睡眠が毎日 6〜9 時間ある ／ 仕事が睡眠と重ならない ／ 勤め先の営業時間の中。
  - 同じ `life` から同じ予定。移行を 2 回流しても変わらない。途中で止めてやり直しても同じ。
  - 20 人作ると型が 4 種類以上に分かれ、平日 14 時に「仕事中」の人が全員にはならない。
  - 移行: ひなは予定が変わらない ／ 写しの人は変わる ／ 手で直した予定は残る ／ `schedule_old` が残る ／ バックアップができる。
  - ワールド: 作り直した人の知っている予定だけ消える ／ 2 つ目のワールドは開いたときに処理される ／ 二度は走らない。
  - `rhythm`: 夜勤の人で落ちない・昼に寝坊が付く・残業が朝に付く ／ ひなの揺らぎは移行の前後で同じ。
  - 既存: `test_schedknow`・`test_calendar`・`test_dawn`・`test_encounters`・`test_appoint_change` が通る。
- 段 2
  - 状態（`asked` / `offered` / `set` / `waiting` / `favor` / `favor fixed`）× 都合（つく / つかない / 空きが無い）× 約束までの時間（1 時間未満 / 3 時間未満 / それ以上）の総当たりで、4. の表どおり。
  - 打診の一言がトークに 1 通だけ・`rounds` が増えない・`her_moved` が付く・受ける / 断る / 別の日時がいまの流れで通る。
  - 複数人の打診が同じ時刻に固まらない。相手が寝ている時刻には来ない。開き直しても二重に送らない。
- 段 3
  - 型ごとに 90 日: 平均の月の貯まり方が目標の ±2 割 ／ 0 円を下回らない ／ 給料日に増える ／ 在宅は月ごとに揺れる。
